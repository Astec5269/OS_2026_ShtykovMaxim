# Лабораторная работа №1\. Процессы и каналы

## Назначение

Программа вычисляет сумму целых чисел в каждой введённой строке и записывает
результаты в текстовый файл\. Обработка организована в двух процессах,
взаимодействующих через неименованные каналы\.

Пользователь первой строкой вводит имя выходного файла, затем — строки
чисел типа `int`\. Количество чисел в строке заранее не задаётся\.
Для каждой корректной строки в файл записывается одна сумма\.

## Язык и среда выполнения

- Язык: **C, стандарт C99** &#40;`-std=c99`&#41;\.
- Операционная система: Ubuntu/Linux\.
- Управление процессами и обмен данными: интерфейсы POSIX\.
- Ввод\-вывод: `read`, `write`, `open`, `close`\.
- `stdio.h` и его функции не используются\. Разбор чисел и преобразование
  суммы в текст выполняются собственными функциями\.

`fork`, `pipe`, `dup2`, `execv` и `waitpid` относятся к интерфейсам POSIX,
а не к стандартной библиотеке ISO C\. Код компилируется как C99 в среде
Ubuntu/Linux\. Поиск исполняемого файла через `/proc/self/exe` также
привязан к Linux\.

## Структура проекта

|Файл            |Назначение                                                                                         |
|----------------|---------------------------------------------------------------------------------------------------|
|`parent.c`      |Родительская программа: ввод, создание процесса, настройка каналов, передача данных и получение эха|
|`child.c`       |Дочерняя программа: разбор чисел, вычисление сумм и запись в файл                                  |
|`CMakeLists.txt`|Настройки сборки двух отдельных исполняемых программ в стандарте C99                               |
|`README.md`     |Описание реализации, сборки и использования                                                        |

`parent.c` и `child.c` компилируются отдельно\. Каждый файл содержит свой
`main` и необходимые вспомогательные функции\. Пользователь запускает только
`parent`; программа `child` запускается родителем\.

## Организация обмена

Создаются два однонаправленных канала:

|Канал  |Отправитель                     |Получатель                     |Данные               |
|-------|--------------------------------|-------------------------------|---------------------|
|`pipe1`|Родитель, `pipe1[1]`            |Ребёнок, через стандартный ввод|Исходные строки чисел|
|`pipe2`|Ребёнок, через стандартный вывод|Родитель, `pipe2[0]`           |Эхо полученных байтов|

Элемент `[0]` массива дескрипторов используется для чтения, `[1]` — для записи\.
Массив хранит номера дескрипторов; буфер канала находится в ядре ОС\.

Суммы записываются ребёнком непосредственно в выходной файл\. Через `pipe2`
возвращаются исходные данные\. Родитель выводит это эхо в консоль\.
Эхо подтверждает получение блока ребёнком, но не обязательно завершение
целой команды: один блок может содержать только часть строки\.

Сообщения об ошибках выводятся через `stderr`, который остаётся подключённым
к консоли\. Успешность завершения ребёнка проверяется родителем через `waitpid`\.

## Работа родительской программы

1. Настраивает обработку записи в канал без читателя: сигнал `SIGPIPE`
   игнорируется, чтобы `write` вернул ошибку `EPIPE`\.
2. Читает имя выходного файла первой строкой стандартного ввода\. Проверяет,
   что имя непустое и помещается в буфер\.
3. Через `readlink("/proc/self/exe", ...)` определяет каталог своей программы
   и формирует путь к расположенному рядом исполняемому файлу `child`\.
4. Создаёт `pipe1` и `pipe2`, затем вызывает `fork`\.
5. В дочерней ветке закрывает неиспользуемые концы каналов и выполняет:

```c
dup2(pipe1[0], STDIN_FILENO);
dup2(pipe2[1], STDOUT_FILENO);
```

После перенаправления закрывает исходные дескрипторы этих концов и через
`execv` запускает `child`, передавая имя файла в `argv[1]`\.
6\. В родительской ветке закрывает читающий конец `pipe1` и пишущий конец `pipe2`\.
7\. Читает ввод блоками до 4096 байтов, передаёт данные ребёнку и получает
обратно такое же количество байтов эха\. Пустая строка завершает ввод
и ребёнку не передаётся\.
8\. Закрывает оставшиеся дескрипторы и вызывает `waitpid` для получения
статуса завершения ребёнка\.

`fork` создаёт процесс, а `execv` заменяет выполняемую в дочернем процессе
программу\. При успешном `execv` выполнение начинается в программе `child`;
возврата к следующей инструкции родительского исходника не происходит\.

## Работа дочерней программы

1. Проверяет наличие аргумента с именем выходного файла\.
2. Открывает файл:

```c
open(argv[1], O_WRONLY | O_CREAT | O_TRUNC | O_APPEND, 0600);
```

Файл создаётся при отсутствии, существующее содержимое очищается\.
Каждая последующая запись выполняется в конец файла\. Права нового файла —
чтение и запись для владельца, с учётом `umask`\.
3\. Читает блоки из стандартного ввода, подключённого к `pipe1`\.
4\. Последовательно разбирает символы\. При завершении числа добавляет его
к сумме текущей строки\. При `\n` записывает сумму и перевод строки в файл\.
5\. Возвращает полученный блок родителю через стандартный вывод,
подключённый к `pipe2`\.
6\. При EOF обрабатывает последнюю незавершённую переводом строки команду,
если она содержит число или обнаруженную ошибку, и закрывает файл\.

## Разбор чисел и состояние обработки

Состояние хранится в структуре `Parser`, созданной до цикла чтения:

|Поле         |Назначение                                 |
|-------------|-------------------------------------------|
|`magnitude`  |Модуль текущего числа                      |
|`sum`        |Сумма законченных чисел текущей строки     |
|`in_token`   |Признак начавшегося числа                  |
|`negative`   |Признак отрицательного знака               |
|`digits`     |Признак наличия цифр в текущем числе       |
|`have_number`|Признак наличия законченного числа в строке|
|`invalid`    |Признак ошибки ввода или переполнения      |

`consume` обрабатывает очередной символ\. Цифры накапливаются по правилу
`magnitude = magnitude * 10 + digit`\. Пробельный разделитель вызывает
`finish_number`: она учитывает знак и добавляет число к сумме\.

При переводе строки вызывается `save_sum`: завершает последнее число,
проверяет корректность команды, записывает результат и обнуляет состояние
для следующей строки\.

Например, строка `12 -5 8` даёт последовательные суммы `12`, `7`, `15`\.
В файл записывается `15` с переводом строки\.

## Соображения реализации

### Потоковая обработка

Канал передаёт поток байтов и не сохраняет границы отдельных вызовов `write`\.
Один `read` может вернуть несколько строк, часть строки или часть числа\.
Поэтому границей команды служит `\n`, а состояние `Parser` сохраняется между
чтениями\. Буфер 4096 байтов не ограничивает длину строки и количество чисел\.
Хранить все числа строки в массиве не требуется\.

### Тип суммы

Каждая входная величина проверяется на диапазон `int`\. Сумма хранится
в `long long`, чтобы результат сложения нескольких допустимых `int` мог
выходить за диапазон `int`\. Переполнение `long long` также проверяется\.
Арифметика произвольной точности не используется\.

### Полнота передачи

`write_all` учитывает частичную запись и продолжает передачу оставшихся
байтов\. `receive_echo` дочитывает ровно переданное количество байтов:
один вызов `read` не обязан вернуть полный ответ\.

### Завершение и освобождение ресурсов

Неиспользуемые концы каналов закрываются в обоих процессах\. После закрытия
родителем пишущего конца `pipe1` ребёнок дочитывает данные и получает EOF\.
Оставленная открытой лишняя копия пишущего конца помешала бы получить EOF\.
Родитель закрывает канал до ожидания ребёнка через `waitpid`\.

### Текстовый формат

`put_number` преобразует сумму в десятичные символы без `stdio.h`\.
Результат записывается как текст, после каждой суммы добавляется `\n`\.
Завершающий нулевой байт в выходной файл не записывается\.

## Правила ввода и ошибки

Допускаются положительные и отрицательные целые числа, необязательный знак
`+`, пробелы и табуляция между числами\. Несколько разделителей подряд допустимы\.

|Ввод                          |Результат          |
|------------------------------|-------------------|
|`12 -5 8`                     |Сумма `15`         |
|`+3 0 -7`                     |Сумма `-4`         |
|`1   2`                       |Сумма `3`          |
|Пустая строка                 |Завершение ввода   |
|Строка только из пробелов     |Ошибка             |
|`12 abc`, `2.5`, `1, 2`       |Ошибка формата     |
|`+`, `-`, `1-2`               |Ошибка формата     |
|Число за пределами `int`      |Ошибка диапазона   |
|Переполнение суммы `long long`|Ошибка переполнения|

При некорректной команде программа завершается с ошибкой\. Повторный ввод
этой команды не предлагается; суммы ранее обработанных корректных строк
остаются в файле\. Сумма некорректной строки не записывается\.

Проверяются ошибки создания каналов и процесса, перенаправления потоков,
запуска `child`, открытия файла, чтения, записи, закрытия и ожидания ребёнка\.
Прерванные сигналом операции чтения, записи и ожидания повторяются при
`EINTR`\. При ошибке `execv` дочерняя ветка завершается через `_exit`\.

## Сборка и запуск в Ubuntu

Из каталога проекта:

```sh
gcc -std=c99 -Wall -Wextra -Wpedantic parent.c -o parent
gcc -std=c99 -Wall -Wextra -Wpedantic child.c -o child
./parent
```

Либо через CMake:

```sh
cmake -S . -B build
cmake --build build
./build/parent
```

В `CMakeLists.txt` задано:

```cmake
set(CMAKE_C_STANDARD 99)
set(CMAKE_C_STANDARD_REQUIRED ON)
set(CMAKE_C_EXTENSIONS OFF)
```

Оба исполняемых файла должны находиться в одном каталоге\. Программа ожидает
открытые стандартные дескрипторы `stdin`, `stdout`, `stderr` при запуске\.

Зависимость `add_dependencies(parent child)` обеспечивает сборку отдельной
программы `child` при сборке цели `parent`.

Относительное имя выходного файла отсчитывается от рабочей папки запуска.
Можно указать абсолютный путь внутри Ubuntu.

## Пример использования

Первой строкой ввести `result.txt`, затем команды:

```text
1 2 3
10 -5 7
100
```

После последней команды нажать Enter на пустой строке для завершения\.
В обычном терминале Ubuntu также можно завершить ввод через Ctrl\+D
на пустой строке\.

Содержимое `result.txt`:

```text
6
12
100
```

Родитель выводит полученное от ребёнка эхо исходных строк\. В обычном
терминале числа могут отображаться дважды: сначала терминал показывает
ввод, затем программа печатает эхо\.

## Проверка реализации

Оба исходника скомпилированы на Ubuntu компилятором GCC в стандарте C99 с параметрами
`-Wall -Wextra -Wpedantic -Werror`; проверен запуск собранной программы\.

Для реализации проверены границы `int`, сумма больше `INT_MAX`, EOF без
перевода строки, строка из 20000 чисел, разрыв числа на границе буфера,
несколько строк за чтение, завершение пустой строкой, некорректный ввод,
случайные суммы, ошибки открытия и записи файла, отсутствие программы `child`\.
