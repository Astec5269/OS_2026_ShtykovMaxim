# Лабораторная работа №2. Многопоточность

## Назначение

Вариант 3: отсортировать массив целых чисел параллельной сортировкой
слиянием. Реализованы две отдельные программы: последовательная и
параллельная. Сортировка выполняется по возрастанию.

## Язык и среда выполнения

Программы написаны на языке C (стандарт C99) и скомпилированы
в Ubuntu компилятором GCC. Для создания потоков и синхронизации
используются POSIX Threads: `pthread_create` и `pthread_join`.

## Структура проекта

| Файл | Назначение |
|---|---|
| `sequential.c` | Последовательная программа со своим `main` |
| `parallel.c` | Параллельная программа со своим `main` |
| `common.h` | Общие функции ввода, слияния, последовательной сортировки и измерений |
| `CMakeLists.txt` | Сборка двух исполняемых файлов |
| `benchmark.py` | Вспомогательный скрипт экспериментов (Python 3) |
| `README.md` | Описание алгоритма, сборки, запуска и экспериментов |

Сами алгоритмы реализованы на C; Python только запускает готовые программы
и рассчитывает показатели. `common.h` должен лежать рядом с обоими исходниками.

## Сборка в Ubuntu

Из каталога проекта:

```sh
gcc -std=c99 -O2 -Wall -Wextra -Wpedantic sequential.c -o sequential
gcc -std=c99 -O2 -Wall -Wextra -Wpedantic -pthread parallel.c -o parallel
```

Флаг `-pthread` включает поддержку POSIX Threads. Для честного сравнения
обе версии собираются с одинаковым уровнем оптимизации `-O2`.

## Ввод и запуск

Первая величина — размер массива N (может быть нулевым), затем N целых
чисел типа `int`, разделённых пробельными символами. Переводы строк допустимы.
После N элементов программа начинает сортировку; EOF ждать не требуется.

```sh
printf '8\n5 -2 9 0 5 1 -7 3\n' | ./sequential
printf '8\n5 -2 9 0 5 1 -7 3\n' | ./parallel -t 4
```

Обе программы выводят:

```text
-7 -2 0 1 3 5 5 9
```

Ввод из файла и сохранение результата:

```sh
./parallel -t 4 < input.txt > output.txt
```

В `stderr` отдельно выводятся размер массива, лимит потоков, время в
миллисекундах и результат проверки порядка. Поэтому эти сведения не
попадают в `output.txt` при обычном перенаправлении `>`.

### Ключи

| Ключ | Значение |
|---|---|
| `-t P` | Лимит потоков параллельной программы; по умолчанию 1, P ≥ 1 |
| `-n N` | Сгенерировать массив из N элементов вместо чтения stdin |
| `-s S` | Начальное значение генератора; по умолчанию 42 |
| `-k random` | Псевдослучайные числа от −1000000 до 1000000; по умолчанию |
| `-k sorted` | Сгенерированные числа в возрастающем порядке |
| `-k reverse` | Сгенерированные числа в убывающем порядке |
| `-k equal` | Все элементы равны 7 |
| `-q` | Не печатать массив; сведения о времени остаются |
| `-d` | Только parallel: задержка для демонстрации потоков через ОС |

`-s` и `-k` относятся к генерации с `-n`. Одинаковые N, seed и тип данных
дают один и тот же исходный массив в обеих программах.

```sh
./sequential -n 1000000 -s 42 -q
./parallel -n 1000000 -s 42 -t 4 -q
```

## Последовательная сортировка

`merge_sort(a, tmp, left, right)` работает с полуинтервалом `[left, right)`:

1. Если элементов меньше двух, сортировать нечего.
2. Вычисляется середина `mid = left + (right - left) / 2`.
3. Рекурсивно сортируются `[left, mid)` и `[mid, right)`.
4. Функция `merge` объединяет две отсортированные части во временном массиве.
5. Результат копируется обратно в исходный массив.

При равенстве выбирается элемент левой части (`<=`), поэтому сортировка
устойчивая. Время — O(N log N), дополнительный массив — O(N).

## Параллельная сортировка

Структура `ThreadArgs` содержит указатели на исходный и временный массивы,
границы участка, бюджет потоков `budget` и признак демонстрации.

Функция `work`:

1. При бюджете 1 выполняет обычную последовательную сортировку участка.
2. Иначе делит участок пополам, бюджет — на `budget / 2` и остаток.
3. Через `pthread_create` запускает левую часть в новом потоке.
4. Сама обрабатывает правую часть в текущем потоке.
5. Через `pthread_join` ожидает левую часть.
6. Сливает результаты в текущем потоке.

Это рекурсивная модель fork–join: создание потока → независимая работа →
ожидание → объединение результатов. Само каждое слияние последовательное,
но сортировка частей и независимые слияния разных ветвей идут параллельно.

### Ограничение числа потоков

**P включает основной поток.** При `-t 4` создаётся не более трёх дополнительных
потоков. При `-t 1` новых потоков нет. Когда P > N, бюджет уменьшается до N
(для пустого массива используется 1).

Бюджеты дочерних задач в сумме равны бюджету родителя. Новый поток относится
к левому бюджету, текущий — к правому. Поэтому во всём дереве не может
существовать больше P потоков одновременно, в том числе ожидающих в `join`.
За весь запуск создаётся P−1 дополнительных потоков после ограничения по N.
Реальное число одновременно существующих потоков может быть меньше P,
если отдельные ветви уже завершились. Не каждый существующий поток занят
вычислениями: часть ожидает завершения другой ветви.

### Синхронизация и отсутствие гонок

Левая и правая задачи пишут в непересекающиеся участки `a` и `tmp`.
Слияние родителя начинается только после завершения обеих задач.
`pthread_join` обеспечивает ожидание и видимость результатов дочернего потока.
Мьютекс для массива не требуется: совместной записи в один элемент нет.

Аргументы дочернего потока — локальная структура `left`; она существует
до `pthread_join`, поэтому указатель не становится недействительным раньше времени.
Память массивов освобождается после окончания всей сортировки.

## Измерение времени

Используется `clock_gettime(CLOCK_MONOTONIC)`: измеряется прошедшее реальное
время, а не сумма процессорного времени всех потоков.

В измерение входят сортировка, создание и ожидание потоков, все слияния.
Чтение/генерация данных, выделение массивов, проверка и печать результата
в измерение не входят. Подготовительная сортировка данных для `-k sorted`
и `-k reverse` также выполняется до измерения.

Режим `-d` добавляет искусственную задержку внутрь измеряемого участка.
**Время с `-d` нельзя использовать для сравнения производительности.**

## Демонстрация потоков средствами Ubuntu

Запустить в терминале:

```sh
./parallel -n 1000000 -t 4 -q -d &
pid=$!
sleep 1
ps -T -p "$pid" -o pid,spid,stat,comm
ps -o pid,nlwp,comm -p "$pid"
grep '^Threads:' /proc/"$pid"/status
wait "$pid"
```

В демонстрационном режиме конечные задачи ждут около 10 секунд.
При четырёх потоках и достаточном размере массива `NLWP` / `Threads`
показывают 4, а `ps -T` — четыре строки потоков. Строка основного потока
также входит в счёт. Состояние сна во время задержки нормально.

## Исследование ускорения и эффективности

Число логических процессоров:

```sh
getconf _NPROCESSORS_ONLN
```

Автоматическое исследование:

```sh
python3 benchmark.py > results.md
```

По умолчанию проверяются N = 100000 и 1000000, четыре вида входных данных,
по три измерения каждого режима плюс прогрев. В таблицу попадает медиана.
Для каждого повтора обе программы получают одинаковый seed.
Запуски выполняются последовательно, чтобы не конкурировать друг с другом.

Если C ≥ 5, набор P = 1, 2, 3, 4, C, 4C, 8C, 16C даёт требуемые
четыре значения меньше C, одно равное C и три значительно больше C.
При C < 5 четыре различных положительных значения меньше C выбрать
невозможно; скрипт сообщает об этом ограничении.

Свои параметры:

```sh
python3 benchmark.py --sizes 100000 1000000 5000000 --repeats 5 > results.md
python3 benchmark.py --threads 1 2 3 4 8 32 128 1024 > results.md
```

Второй пример рассчитан на систему с 8 логическими процессорами.
Если ОС отказывает в создании потоков из-за нехватки ресурсов,
скрипт записывает сообщение об ошибке вместо времени и показателей.

Формулы:

- `S(P) = Tseq / Tp` — ускорение, во сколько раз параллельная версия быстрее.
- `E(P) = S(P) / P` — эффективность использования выделенного бюджета потоков.
- `E_percent(P) = 100 * S(P) / P` — эффективность в процентах.

Здесь `Tseq` — время отдельной последовательной программы, `Tp` — время
параллельной при лимите P. Параллельная версия с P = 1 тоже измеряется,
но не подменяет последовательную базу сравнения.

Значение S > 1 означает ускорение, S < 1 — замедление.
Эффективность характеризует отношение ускорения к числу выделенных
потоков и не является процентом загрузки процессора.

## Обработка ошибок и проверка результата

Проверяются формат аргументов, размер массива, диапазон `int`, нехватка
введённых чисел, выделение памяти, создание и ожидание потоков.
При ошибке программа завершается ненулевым кодом и не выдаёт частично
отсортированный массив как успешный результат.

Для проверки корректности используются пустой массив, один элемент,
отрицательные числа, повторы, граничные значения `int`, упорядоченные
и обратные массивы, нечётные размеры и разные лимиты потоков.
После каждой сортировки программа проверяет порядок элементов.
