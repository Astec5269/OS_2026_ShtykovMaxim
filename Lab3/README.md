# Суммирование строк через разделяемую память

Лабораторная работа по операционным системам, вариант 1. Язык — C99. Программы скомпилированы и проверены на Ubuntu 24.04.3 LTS.

## Задание

Родительский процесс получает имя выходного файла, затем строки целых чисел типа `int`. Дочерний процесс вычисляет сумму каждой строки и записывает результаты в файл. Программы родителя и ребёнка компилируются отдельно. Обмен выполняется через именованный объект POSIX shared memory, отображённый в адресные пространства процессов через `mmap`. Для синхронизации используются именованные семафоры.

## Структура

| Файл | Назначение |
| --- | --- |
| `server.c` | Родитель: ввод, создание IPC, `fork` и `execv`, передача блоков, ожидание ребёнка и освобождение ресурсов. |
| `client.c` | Ребёнок: подключение к IPC, разбор чисел, вычисление сумм и запись файла. |
| `ipc.h` | Общая структура памяти и вспомогательные функции ввода-вывода, ожидания и сообщений об ошибках. |
| `test.py` | Автоматическая сборка и 23 проверки. Нужен Python 3 только для тестирования. |

`ipc.h` подключается к обеим программам, отдельно компилировать его не нужно. Результат сборки — два исполняемых файла: `server` и `client`.

## Сборка и запуск

В каталоге исходных файлов выполните:

```bash
cc -std=c99 -Wall -Wextra -Wpedantic server.c -o server -pthread -lrt
cc -std=c99 -Wall -Wextra -Wpedantic client.c -o client -pthread -lrt
./server
```

Исполняемые файлы должны находиться рядом. `server` находит `client` относительно собственного расположения через `/proc/self/exe`; текущий рабочий каталог может быть другим. Самостоятельно запускать `client` не требуется.

Пример ввода после запуска:

```text
result.txt
1 2 3
10 -5 7
100

```

Первая строка — имя файла. Последняя пустая строка завершает работу. В терминале выводится эхо обработанных блоков. В `result.txt` окажется:

```text
6
12
100
```

Файл создаёт дочерний процесс; существующее содержимое файла стирается при открытии. Относительный путь отсчитывается от рабочего каталога запуска. Права нового файла — `0600` с учётом `umask`.

## Организация взаимодействия

1. `server` читает имя файла. Создаёт объект `shm_open` с флагами `O_CREAT | O_EXCL | O_RDWR`, устанавливает размер через `ftruncate`, отображает его через `mmap` с `MAP_SHARED` и правами чтения и записи.
2. Создаются два именованных семафора: `request` и `reply`, оба с начальным значением 0. Имена памяти и семафоров содержат PID и время запуска. Разные экземпляры используют независимые объекты; `O_EXCL` не позволяет захватить уже существующий объект при совпадении имени.
3. `fork` создаёт второй процесс. В дочерней ветке `execv` заменяет программу на `client`; имя файла и имена IPC передаются аргументами. `execv` не создаёт третий процесс.
4. `client` открывает объекты по переданным именам, выполняет своё отображение памяти и открывает выходной файл. Через `reply` сообщает результат запуска.
5. Родитель удаляет имена объектов через `shm_unlink` и `sem_unlink`: оба процесса уже подключены. Сами открытые объекты остаются доступны до освобождения последних ссылок. Такой порядок уменьшает риск оставления IPC после аварийного завершения.
6. Родитель помещает очередной блок в общую память и вызывает `sem_post(request)`. Ребёнок просыпается, разбирает блок, записывает суммы законченных строк, устанавливает статус и вызывает `sem_post(reply)`.
7. Только после подтверждения родитель выводит эхо сохранённого в общей памяти блока и может записать следующие данные. При ошибке обработка прекращается.
8. При завершении ввода родитель передаёт специальную длину `UINT32_MAX`. Ребёнок обрабатывает последнюю незавершённую строку, закрывает файл и подтверждает завершение. Родитель вызывает `waitpid` и проверяет статус.

Два семафора задают очередность владения одним буфером. Родитель не перезаписывает данные до подтверждения, ребёнок не читает буфер до уведомления. Дополнительный семафор-мьютекс не требуется. Начальное подтверждение запуска использует `reply`, затем через него приходят подтверждения обработки.

Для ожидания используется `sem_timedwait`: это ожидание семафора с ограничением одного интервала. По истечении секунды проверяется состояние второго процесса, после чего ожидание продолжается. Суммарное время ожидания не ограничено. Родитель обнаруживает завершение ребёнка через `waitpid(..., WNOHANG)`, ребёнок проверяет родителя. Это позволяет выйти с ошибкой, если `execv` не удался или другой процесс завершился, вместо бесконечного ожидания подтверждения.

## Что находится в памяти

```c
typedef struct {
    uint32_t length;
    int status;
    char data[4096];
} Shared;
```

`length` — число байтов данных либо маркер завершения. `status` — результат запуска/обработки: 0 означает успех, 1 — ошибку. `data` — фрагмент входного текста. Общий размер объекта определяется `sizeof(Shared)`, а 4096 — только размер поля данных.

`shm_open` создаёт именованный объект общей памяти. `mmap` отображает его в виртуальную память конкретного процесса. Это разные операции: адреса отображений могут различаться, но данные общие. Для обмена не создаётся обычный дисковый файл; выходной файл хранит только результаты. В Linux именованные POSIX-объекты обычно представлены в `/dev/shm` на `tmpfs`.

Стандартный ввод принадлежит родителю. Дочерний процесс получает команды из памяти. Перенаправление `stdin`/`stdout` через `dup2` и каналы `pipe` для обмена не используются. Эхо в терминал выводит родитель после подтверждения ребёнка.

## Разбор и проверка ввода

- Каждая строка содержит одно или несколько десятичных целых чисел, разделённых пробелами или табуляцией. Поддерживаются знаки `+` и `-`; также распознаются пробельные разделители `\r`, `\v`, `\f`.
- Проверяется диапазон `INT_MIN…INT_MAX`. На проверенной Ubuntu это −2147483648…2147483647.
- Сумма хранится в `long long`; каждое сложение проверяется на переполнение. Поэтому сумма нескольких допустимых `int` может превышать `INT_MAX`.
- `Parser` сохраняет состояние между блоками. Фиксированный буфер не ограничивает длину строки или число слагаемых: число может начинаться в одном блоке и заканчиваться в другом.
- Перевод строки завершает команду и записывает одну сумму. EOF также завершает последнюю команду без `\n`.
- Пустая строка, состоящая непосредственно из `\n`, останавливает ввод. Строка из пробелов с `\n` считается ошибочной командой. Файл с CRLF поддерживается для непустых числовых строк; пустая строка CRLF не является командой завершения.
- Буквы, дроби, одиночный знак, число вне диапазона и переполнение суммы завершают программу с ненулевым кодом. Ранее записанные суммы остаются; сумма ошибочной строки не записывается. При ошибке записи возможна частичная запись последнего результата.

## Обработка ошибок и ресурсы

Ввод-вывод выполняется через `read`, `write`, `open`, `close`, без `stdio.h`. Функция `write_all` обрабатывает частичную запись, прерванные операции повторяются при `EINTR`. Системные ошибки выводятся в `stderr` с именем операции и числом `errno`.

При обработанной ошибке родитель при необходимости завершает ребёнка, вызывает `waitpid`, закрывает семафоры и дескрипторы, снимает отображение. Имена удаляются только для созданных этим запуском объектов. После штатного завершения именованных объектов не остаётся. Принудительное завершение до стартового подтверждения может оставить ещё не удалённые имена; очистка после `SIGKILL` на этом этапе не гарантируется.

## Проверка

```bash
python3 test.py
```

Проверены 23 случая: несколько строк, отрицательные числа, нули, знаки и пробелы, границы `int`, сумма больше `INT_MAX`, EOF, пустая строка, некорректные значения, строка из 100000 единиц, число на границе буфера, 5000 команд, ошибки открытия и записи файла, отсутствие `client`, независимые параллельные запуски и отсутствие оставшихся имён IPC. Все проверки пройдены на Ubuntu 24.04.3 LTS; сборка тестов дополнительно использует `-Werror`.
